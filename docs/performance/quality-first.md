# 速度・品質を維持する原価削減

実装の優先順位は応答速度、内容品質、安定性、原価。安価なモデルへの自動切り替えや文脈削除は、比較試験を通過するまで導入しない。

## 現在の変更

- `pnpm performance:assess <soak.json>` で保存したブラウザー試験の計測を再評価する。
- 応答速度は既存HUDの厳しい目標を維持し、p50 ≤ 700ms、p95 ≤ 1500ms、100サンプル以上を要求。
- 割り込みは現在のHUDで停止要求→停止の最大値 ≤ 150ms、20サンプル以上。これはユーザー発話開始からの時間ではない。
- 聞き取り数/入力発話数と応答数/聞き取り数をそれぞれ98%以上要求。件数・時刻による近似であり意味内容の正しさは別評価。
- ページ、HTTP、コンソールのエラーを不合格とし、欠けた測定はBLOCKED。
- WAVのループ回数を入力発話数へ反映。同じ応答を複数の入力に重複して対応させない。
- 公開リリース判定の応答速度・割り込みp95条件も強化。性能試験だけで公開可とはしない。

## 保存済みの実測から分かること

`docs/reports/soak/google-2026-09-08T00-23-41.json` は旧判定PASSだが、HTTP 502とコンソールエラーで新判定FAIL。p50 1282ms / p95 1541ms、6サンプルであり新しい速度基準の合格証拠にはならない。元の報告は変更せず保持する。

`docs/reports/soak/local-2026-09-08T00-12-36.json` は入力71発話に対し聞き取り28発話。ローカル化による原価削減を品質改善とみなさない。

## 次の計測と改善

1. 実マイク・実会議で発話終了→PC再生開始→遠端で聞こえる時刻を分離して測る。テキスト入力→API初音は代用にならない。
2. 会議Botの600ms割り込み確認待ちを含め、発話開始→停止を測る。停止要求→停止のみで200ms達成としない。誤割り込み率を同時に評価する。
3. 同一の実会議でAPIが返す利用量と請求明細を突き合わせ、会議時間あたり原価を算出する。送信音声の削減率をそのまま請求削減率とみなさない。
4. 常時接続と音声ストリーミングを維持し、重複処理・不要な映像・待機ワーカーを優先して削減する。
5. 必要な記憶の検索・資料解析を並行化する際も、未確認の回答を先に話させない。60分会議の決定事項・担当者・条件を人間が照合する。

新たなダミー音声・モック・架空の試験結果はこの変更で追加しない。既存の合成音声soakは今回実行せず、保存済み計測の再評価だけ行った。実会議での目標達成、原価削減率、Release=GOは未検証。
