# 5名・3分音声のチーム導入

この提供単位は `team-tasks-3m-v1`。30日間・5名・100タスクの共有と、1回180秒の日本語音声によるタスク整理です。会議ボット、録音保管、長時間会議、SSO、医療・金融等の判断、機密情報の投入は対象外です。企業全体の本番認定と、この範囲の技術的な受入判定を分けます。

## 人手を省く仕組み

- メール確認済みの利用者がチームを作成でき、管理者は相手のメールに限定した48時間・1回限りの招待リンクを発行します。管理者の手動DB設定は不要です。
- 保存先は東京の専用Firestore。Firebase IDをサーバーで検証し、チームの参加権限を各操作で確認します。ブラウザーからDBを直接読むことはできません。
- 変更はリビジョンで照合し、権限・利用量・タスク・監査を同じトランザクションで更新します。同時更新や応答不明時に、成功したふりをしません。タスクを削除してもリビジョンを更新し、古い空の状態からの書戻しを拒否します。
- チームではGoogle Vertexの音声のみを使用し、アバターはローカル描画。音声開始前に送信先とタスク共有を表示し、同意のバージョンを監査記録に残します。録音・文字起こし・不具合動画はアプリに保存しません。PIIの自動検出・除去を実装済みという意味ではありません。
- メンバーを外す、チームを閉鎖する、利用期限を迎えると、新しい操作を拒否します。接続中の音声は15秒ごとの確認と5秒の確認期限で停止し、マイクを解放します。端末やネットワークによる遅延のない保証ではありません。
- 30日後にチーム情報とタスクが削除対象になります。期限後の読み書きはTTLの実削除を待たずに拒否します。監査記録は内容を含まず90日で削除対象。FirestoreのTTLは即時削除ではありません。
- タスクのJSON保存・復元に加え、専用DBのPITRを有効化し、毎日のバックアップを7日保持する設定にします。削除直前の履歴を読み、合成データを復元する実試験を行います。日次バックアップの設定と、最初のバックアップ完了は別に記録します。

管理者用の画面でメンバー、音声予約数、タスク削除、閉鎖、直近100件の操作記録を確認できます。チーム名・メンバー表示名はチームの情報として保存し、招待メールはハッシュで照合します。利用者によるJSONダウンロードはこの削除管理の対象外です。Firebaseのログインアカウント削除は共有チームのタスク削除と別です。管理者は先にチームを閉鎖してください。

## 費用を増やし続けない制御

提供全体の既存上限（UTC月30予約・1人UTC日1予約・180秒）を維持します。チームはUTC日3予約・累計20予約、操作はUTC日1,000回まで。限定提供のチーム作成枠は合計10個です。内部の実接続検証も枠を使い、失敗・閉鎖・アカウント削除でカウンターを戻しません。これらは円建てのクラウド請求上限ではありません。枠に達すると新規作成・音声を停止し、可能な範囲で入力による整理を続けます。

```sh
pnpm typecheck

node scripts/cloud/team-infrastructure.mjs
# 検証対象の候補を team-check タグへ配置し、そのURLでViteをビルドして5180で起動する。
GOOGLE_CLOUD_PROJECT=gen-lang-client-0307428960 TEAM_LIVE=1 pnpm exec tsx scripts/verification/team-cloud.mts
TEAM_BROKER_URL=https://team-check---ai-meeting-broker-pdygkns5gq-an.a.run.app node scripts/verification/team-readiness.mjs
node scripts/cloud/promote-team.mjs ai-meeting-broker-REPLACE-WITH-VERIFIED-REVISION
```

最後のコマンドは候補と検証結果、上限、DB保護・TTL・バックアップ設定を確認してからトラフィックを切り替えます。公開後のチェックが失敗した場合は直前のリビジョンに戻します。他のデプロイが並行していた場合には勝手に上書きしません。認証情報はADCで取得し、Gitや検証JSONに保存しません。

`team-cloud.mts` は専用の合成アカウントを作り、実画面から作成・保存・招待・別アカウント同期を実行します。別企業のアクセス拒否、競合、保存失敗、実Vertex応答からのチーム保存、接続中の権限取消、削除、履歴復元、直接DB読取拒否まで試します。最後に合成アカウントとそのデータを削除し、容量・音声の利用履歴は保持します。実人間の会話品質・100人の実績の代替ではありません。

## 障害時

`GET /api/team/status` はDB接続も調べ、利用できなければ503を返します。検査を60秒共有キャッシュし、状態確認によるDBアクセスを抑えます。Cloud Monitoringの可用性検査で記録します。DBに接続できない場合に個人用保存先へ切り替えたり、モデルを別事業者へ切り替えたりしません。公開後の合否判定が失敗した場合はリリース処理が自動で切り戻します。クラウド全体の障害からの自律復旧や24時間の人間サポートを保証するものではありません。

復旧で本番DBを過去へ丸ごと戻すと、削除済みデータや取り消した権限まで戻るおそれがあります。復旧先は別DBとし、失効・削除・利用量の最新状態を維持して必要なタスクだけを移します。自動試験は合成チームだけに限定します。
