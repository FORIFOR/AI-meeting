# 公開ゲート用の人による評価

これは実施手順であり、評価結果ではない。`human-rating-template.json` の空欄を実際の参加者の回答で埋める。既存の `docs/human-gate.md` にある少人数の10分試験は初期ベータの手順で、公開要件を代替しない。

1. `node scripts/release/reality.mjs --build-id` で候補版を記録する。検証中にソースや公開ポリシーを変更した場合は別の候補として扱う。
2. 15人以上が、各3セッション以上を実施する。参加者IDは匿名IDとし、同じ人を複数人として数えない。各セッションのID、候補版、使用モード、プラットフォーム、開始・終了時刻を記録する。
3. 各セッションの終了時、参加者本人に次の3項目を1〜5の整数で回答してもらう。「会話は自然だった」「役に立った」「煩わしくなかった」。5が最も肯定的。良い回答に誘導せず、都合の悪いセッションも記録する。
4. 各参加者の3回以上の利用後に「また使いたい」「使えなくなったら困る」を本人のYes/Noで回答してもらう。未回答をNoやYesで埋めない。
5. 問題が起きた場合、時刻・観測した挙動・使用機器を `incidents` に残す。スコアの記入者を `reviewer` に記録し、記入済みの個票では `templateOnly` をfalseにする。録音や個人情報を公開リポジトリへ入れず、集計の根拠を検証者が参照できる場所に保存する。

公開の必要条件は、自然さ平均4.2以上、有用性4.3以上、煩わしくなさ4.5以上（各45セッション以上）、再利用意向80%以上、なくなると困る50%以上（各15人以上）。公開対象の各モードはさらに有用性4.3以上・15標本以上が必要。正式な全要件は `scripts/release/reality.mjs` に従う。

個票を回収した後、候補版・参加者数・各人のセッション数・欠測を確認し、実値と件数を集計する。`evidence.json` には集計値だけでなく、根拠ファイルのパス、SHA-256、測定日時、検証者を登録する。空テンプレート、AIによる代理回答、過去版の結果を候補版の測定として登録しない。
