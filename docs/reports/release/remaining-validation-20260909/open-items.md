# 未完了項目と次の実行条件

## 音声の応答タイミング

公開版の30分試験は完走。中央値1470ms・p95 1818msで、それぞれ700ms・1500msの目標を超えている。確定値はsoakレポートを参照。500msの発話終了待ちは、以前の350msの文中休止で予定時刻を取りこぼした問題を直すために増やされた設定である。今回の測定だけを理由に短く戻し、認識精度を悪化させない。

5声の別試験では、同じ合成入力「こんにちは。明日の午後三時から一時間、英会話を練習したいです。何時に終わるか、短く確認してください。」に対して午後4時と正答した。ただし入力PCMの末尾より先に応答音声を受信し、入力字幕の「確認してください」が欠落した。voice-output.jsonとvoice-assessment.jsonに観測を保存。これは1種類の入力であり、一般の意図認識誤り率や人の満足度を示さない。音声波形の欠損・クリッピング検査と、自然な会話の評価を分ける。

## 実会議・実機

Meet/Zoomそれぞれ、現候補で30分10回・60分3回、実機2台以上。現在のブラウザー単独試験はこの回数に算入しない。待機室・入室拒否・参加者変更・再入室・機器変更・Bluetooth切断・ネットワーク切断など、操作を伴う条件をホストと実機担当者と合わせる必要がある。

必要情報: 使用可能なMeet/Zoomの参加URL、ホストによる承認・操作が可能な時間、実機2台と操作担当者。会議中の第三者への自動メッセージ送信・招待は行わない。今回の実行中には新しい会議Botを作成していない。今後作成したYui/Testerは必ず両方退出させ、終了状態を記録する。

## 遅延設定の確認

Gemini Developer APIのネイティブ音声にはThinking budgetの説明がある一方、使用中のVertexモデル `gemini-live-2.5-flash-native-audio` の公式モデル表ではThinkingが非対応となっている。単に `thinkingBudget: 0` を追加する改善案は採用しなかった。既存コードがVertexでthinkingConfigを省いていることと整合する。[Google公式モデル表（2026-09-09確認）](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/2-5-flash-live-api)
