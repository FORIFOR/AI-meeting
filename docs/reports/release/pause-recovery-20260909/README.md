# 発話途中の区切りによる時刻取りこぼしの修正

## 変更

実Meetテスターの「明日15時から1時間」の録音には、文の途中に約349msの無音があった。Geminiの音声送信ゲートが250msでactivityEndを送り、一つの依頼を分けていた。ゲートを500msに変更し、350ms程度の間を同じ入力として送る。ローカルの音声活動検出は250msを維持する。

加えて、既に開いた入力を保持する処理が、小さい音でも140ms続くと割り込みに数えてしまっていた。割り込みを数えるのは音量しきい値以上が続く場合だけに修正。200msの小さい入力で割り込まない回帰試験は、旧コードで失敗し修正後に成功。

## 確認

- 同じ合成音声を実Vertexへ入力: 250ms設定では後半だけ認識され、予定が分からないとの返答。500ms設定では全文を認識し、開始15時・終了16時と回答。後続質問にも16時と回答。各設定1セッションの比較で、全ケースの成功率を証明するものではない。
- 自動試験716件・70ファイル成功。Gemini型検査とproduction build成功。
- Firebase Hosting version: 87dab804161fddc4。変更により発話終了待ちが最大250ms増えるため、速度の改善とは主張しない。
- source buildId: a3fc2fa0f8b844d320ea0f89a91adfb76b8a744d875eca60a676d4e565b3d3b9。

実Meet再試験は同じ会議に新版YuiとTesterを作成して実施する。公開GO、音質・遅延の全要件、15人×3セッション評価の完了は主張しない。

## 実Meet再試験完了

HostedのYuiとTesterで同じシナリオを実行。開始15時・終了16時と回答し、後続質問にも16時と回答。これらのターンに割り込みイベントなし。指定した割り込みでは停止イベントを確認し、次の質問にGood morningと返答。20秒無言で新しいturnは0。入室挨拶付近に1件の割り込みがあり、全音響品質や物理遅延の合格とはしない。

ユーザーの指示に従い、試験終了後にYuiも退出。Yui・Testerの両方でleft_meetingとendedをAPI確認。以後の試験でも両方を退出させる。公開Releaseは引き続きNO-GO。
